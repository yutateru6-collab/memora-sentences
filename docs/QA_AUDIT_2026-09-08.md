# READON QA audit — 2026-09-08

## Conclusion

The application is reachable and the normal import/reader/study flows pass, but the current application commit is not release-clean. The extended audit found nine distinct, reproducible defects. Four of them affect data integrity or make a feature unusable.

- Application commit under test: `8e24420ae9582143c4d21240aa4e3067261684d7`
- QA workflow run: `34173937884`
- Extended matrix: 20 cases × Desktop Chromium / iPhone Chromium / iPhone WebKit = 60 results
- Extended result: 39 passed, 21 failed (failures include the same defect on multiple targets)
- Normal responsive, knowledge-depth, strict-import, and WebKit regression suites: passed
- Production endpoint availability check: HTTP 200
- Evidence: `qa-latest/latest.json`, `qa-latest/report.json`, `qa-latest/audit-report.json`, 342 screenshot files, and `qa-latest/audit-print.pdf`

The screenshots and generated PDF were opened as images and visually inspected. File presence alone was not treated as visual verification.

## Confirmed defects

| Priority | Area | Reproduction and impact | Evidence / likely cause | Recommended correction |
|---|---|---|---|---|
| High | Import | Paste reading material, then type separate word-card JSON. The reading-material field is silently emptied on all three targets, risking loss of work. | `UploadScreen.tsx:1085` explicitly calls `setPlainTextContent('')`. | Keep the two optional inputs independent. If mutual exclusion is intentional, require an explicit confirmation before clearing. |
| High | Damaged media | Importing a corrupt `.mp3` remains at `取り込み中…` after five seconds with no visible error on all three targets. | `App.tsx:568-574` handles only `loadedmetadata`; there is no `error`, timeout, rejection, or object-URL cleanup. | Reject on media error/timeout, restore the submit state, show a Japanese error, and revoke the object URL. |
| High | Quiz validation | A quiz whose `explanation` is an object is saved, but answering it crashes the entire quiz screen on all three targets. | `QuizCreationModal.tsx:37-48` validates the question, choices, and answer index but not explanation types. React then receives an object as a child in `QuizScreen.tsx`. | Validate every optional explanation as a string before save and show a field-specific import error. Add an error boundary as defense in depth. |
| High | PDF export | A 12-sentence export produced a two-page PDF where both pages repeat the same content and stop part-way through sentence 3; sentences 4-12 are absent. | Visual inspection plus `pdfinfo`/text extraction. The printable node remains inside fixed-height, `overflow-hidden` modal ancestors (`PdfExportModal.tsx:266,303,483`); print CSS only repositions the child. | In print media, reset/hide modal ancestors without clipping, make the print root normal-flow, and add a post-export assertion that all 12 sentence markers occur exactly once. |
| High | Global memo | Desktop Chromium lost `QA memo persisted` after reload in two independent workflow runs. Mobile Chromium retained it; WebKit reached a separate click-interception failure. | Memo save is delayed one second and canceled on effect cleanup (`ReaderScreen.tsx:700-707`); `updateMaterial` resolves on request success rather than transaction completion (`lib/db.ts:279-281`). Exact race cause is strongly suggested but not yet isolated. | Save on blur/unmount, await `transaction.oncomplete`, and test rapid navigation/reload deterministically. |
| Medium | Four-choice game | Four cards sharing the same Japanese meaning render four identical answer buttons; any choice is accepted as correct on all targets. | `GameScreen.tsx:28-47` samples cards, not unique meanings, then compares only the answer string. | Deduplicate meanings before starting; disable the game unless four unique answer values exist. |
| Medium | Word lookup | Clicking `Progress` opens the unrelated `program` card on all targets. | `ReaderScreen.tsx:551-555` treats a shared five-letter prefix as a match. | Remove the fixed five-character prefix rule and use exact tokens plus explicit, tested inflection rules. |
| Medium | WPM | Pressing START and STOP in the same second displays `Infinity WPM` on all targets. | `ReaderScreen.tsx:2343` divides by an elapsed duration of zero. | Clamp elapsed time or show “計測時間が短すぎます” until a minimum interval has elapsed. |
| Medium | Rotation | In iPhone Chromium emulation, rotating 393×852 to 852×393 leaves the Reader at 852px high. Bottom controls remain around y=800 and are outside the 393px viewport. | `ReaderScreen.tsx:239-255` deliberately keeps the maximum height and therefore cannot shrink on orientation change. WebKit emulation did not reproduce the same height result. | Distinguish keyboard resize from an orientation change; reset the stable height when orientation changes. Verify on physical iPhone Safari and Android Chrome. |

The mobile PDF settings screenshot also shows almost no usable preview area because the controls consume most of the 90vh column. This is a UI consequence of the PDF modal layout and should be corrected with the PDF fix.

## Passing coverage

- Production build and application startup.
- Exact 12-sentence / 30-card sample import.
- Safe repairs for code fences, Unicode separators, and trailing commas.
- Atomic rejection of Japanese-only invalid input.
- Desktop and iPhone create, import, Reader, yellow word highlighting, word memo, grammar memo, library reload, deck list, card flip, flashcard grading, and next-card navigation.
- Normal quiz answer/review/bookmark persistence.
- Normal four-choice game progression.
- Personal settings and folder persistence.
- Normal WPM session and RSVP progression.
- Board, Amazon, Legend, and SNS modes, including explanation controls.
- WebKit keyboard shrink/restore, bottom-of-form reachability, touch word selection, and reload regression flow.
- No console/page errors were recorded in the normal responsive suite. The malformed-quiz case intentionally generated the React page error described above.

## QA harness changes only

The audit branch changes only QA automation and this documentation; application source is unchanged.

- Updated three stale UI labels in the existing screenshot flow.
- Made independent follow-up suites run even when an earlier suite fails.
- Added `tools/readon-audit.mjs` with adversarial and all-reachable-screen coverage.
- Corrected the trigger documentation and extended latest-only evidence publication on `qa-latest`.

## Limits and follow-up

This is broad risk-based coverage, not proof that every possible bug is absent. The Actions browsers use isolated synthetic IndexedDB data and do not modify production user data. Physical-device Safari/Chrome, real valid media playback, OS print dialogs, screen readers, external AI generation, multi-gigabyte files, and long-duration endurance were not fully tested. The one WebKit library-card click interception should be repeated on a physical iPhone before it is classified as an application defect.

`npx tsc --noEmit` also reports two unresolved URL imports in `pdfWorker.tsx`. The production Vite build passes and the active PDF UI was tested separately, so this is recorded as a CI/type-check gap rather than a confirmed runtime defect.
